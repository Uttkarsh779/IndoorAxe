## Pricing formula inconsistency found and resolved during implementation
The original had **three separate, hand-copied pricing calculations** with a real drift between them: `orderform` and `quote` both fold the addon cost into the 18% GST base, but `show` (the bill view) recomputes GST from scratch using only the base product cost and silently omits the addon — even though the order being displayed was charged (and its stored `total`/`gst`/`Amount` fields were computed) including the addon. This is a display bug in `show`, not an intentional discount. `pricing.service.js` consolidates all three call sites into one formula that always includes addon cost in the GST base (matching `orderform` and `quote`, and matching what the customer was actually charged) so the bill view now agrees with the amount the customer paid.

## Decisions flagged above that need explicit user sign-off before implementation locks them in
1. `booking`/checkout-PATCH: fix the apparent "creates orphan Order row instead of updating" bug, or replicate it exactly?
2. Razorpay callback signature verification: original doesn't verify HMAC at all (trusts client callback body) — plan adds verification as a security hardening. Confirm this is acceptable (it is strictly safer and shouldn't change any legitimate payment's outcome, only rejects tampered/forged callbacks).
3. `blogs` listing not filtering by `Status_article` in the original template — replicate as-is (showing inactive posts publicly) or filter to `active` only?

## CSRF / security notes for the new API
- Django's per-form `{% csrf_token %}` protected session-cookie POSTs. The MERN API uses a JWT in an httpOnly, `SameSite=Strict` cookie for authenticated routes, which is not vulnerable to classic CSRF in the same way, but `sameSite: 'strict'` + `Origin` header checks (`cors` configured to the frontend origin only) are applied to all state-changing routes as the equivalent protection.
- All monetary calculations happen server-side only (never trust client-submitted totals) — this matches the original, which never received a client-submitted total either.
